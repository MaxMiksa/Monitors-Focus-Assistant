# 开发与构建

已发布 v2.0.0。构建需要Windows、global.json指定的.NET 10 SDK、Node.js 24 LTS、npm及Microsoft Edge WebView2 Runtime。运行成品不需要Node或Vite；自包含打包后不要求另装.NET运行时。

## 工程结构

| 目录 | 职责 |
| --- | --- |
| src/MonitorsFocus | C#托盘核心、DDC/WMI、遮罩、配置、自启；保留旧版入口便于迁移 |
| src/MonitorsFocus.Core | 状态协议、比例计算、每日计划纯计算 |
| src/MonitorsFocus.Web | React/TS界面、Tailwind参数、shadcn源码组件、Motion和Lucide |
| src/MonitorsFocus.WebHost | 薄WinForms窗口承载WebView2；本地资源映射、消息桥和关闭释放 |
| tests/MonitorsFocus.Tests | 无第三方框架的假设备生命周期检查 |
| scripts/build.ps1 | Web优先构建和可选Windows自包含包 |

## 完整构建与启动

```powershell
./scripts/build.ps1
./src/MonitorsFocus.WebHost/bin/Release/net10.0-windows/MonitorsFocus.WebHost.exe
```

本机.NET未加入全局PATH时：

```powershell
./scripts/build.ps1 -Dotnet D:\Apps\dotnet\dotnet.exe
$env:DOTNET_ROOT = 'D:\Apps\dotnet'
$env:DOTNET_ROOT_X64 = 'D:\Apps\dotnet'
./src/MonitorsFocus.WebHost/bin/Release/net10.0-windows/MonitorsFocus.WebHost.exe
```

桌面宿主启动同目录发布包或工作区Release核心，发送 `--center --background`。若旧版已在托盘运行，应先退出旧版，避免旧版单实例锁阻止新核心启动。关闭面板仅退出宿主，核心继续运行；退出核心从托盘菜单操作，并等待硬件恢复。

## 配置迁移与恢复

首次启动且 `control-center.json` 不存在时，读取同目录的 `settings.json`，先备份为 `settings.json.pre-center.bak`，再原子保存新配置。继承 `LaunchOnStartup`、`DelaySeconds`、`HardwareDimLevel` 和语言偏好；原文件及已有备份不改写，已有新配置不再迁移。旧版受控屏和遮罩没有等价的新配置项，仍保留在旧文件供兼容入口使用；热键功能已从两个入口移除，旧配置中的热键字段忽略，兼容入口下次保存时不再写入；新专注保持默认关闭，由用户在新面板中开启。

配置读取或迁移失败会显示错误，核心不按默认配置修改登录自启。自动检查使用独立临时目录，不读写用户配置或注册表。

休眠恢复、热插拔及手动重新检测时，按稳定设备标识保留本次会话的色温目标。新句柄先恢复原色基线，再重新应用目标；初次色温探测失败时保留请求，后台探测成功后执行。断开的设备目标保留到本次核心退出；“恢复原色”同时清空离线设备的保留目标。活动计划仍按当前时间接管，手动保持期不提前结束。退出时即使专注有效亮度未变，也按最新正常亮度恢复临时限制。

## 场景绑定与专注规则

开发版场景在逐屏 `Targets` 之外保存 `Behavior`：绑定开关、独立比例权重、专注开关与受控副屏标识。`ControlledDisplayIds = null` 表示跟随全部副屏，空列表表示不控制任何副屏；主屏无论是否被写入列表都不参与专注调暗。离线设备的目标、比例和受控标识不重新映射到其他屏幕。专注等待时间、专注亮度、全屏保持亮屏选项和临时暂停状态继续使用全局设置。

手动场景切换先保存变化后的当前规则，再应用正常亮度与色温；保存失败时不宣称已切换。时间计划在首次接管、恢复计划或进入新节点时应用同一规则，随后的渐变只更新正常目标，不反复保存配置或重置专注计时。规则变化推进Revision，旧草稿保存时仍提示冲突。重新检测期间保留当前规则；退出时恢复最新正常亮度。

读取旧控制中心配置时，缺少 `Behavior` 的场景各自复制当时的当前规则，不改写原配置文件；之后正常保存时才持久化。新场景从快照捕获正常目标和当前规则，不会把临时专注调暗后的值保存进去。新增5项自动检查覆盖规则保存和副本隔离、旧场景兼容、非法比例拒绝、跨午夜节点规则与受控范围；浏览器模拟桥验证跨页草稿、保存失败保留和新场景捕获。此功能尚未替换本机自包含运行包。

## 操作入口

应用不再注册全局快捷键，也不提供快捷键设置；场景快捷键不在后续需求中。专注暂停、恢复通过控制面板或托盘操作。标准控件的键盘操作保持可用。

## 副屏全屏或最大化时保持亮屏

控制中心的「设置 → 专注」新增同名开关，`KeepSecondaryAwakeOnFullscreen` 默认开启；已有控制中心配置缺少此字段时使用默认值，主动关闭后正常保存。它是专注调暗的例外，关闭专注或暂停时仍按原有规则恢复正常亮度。兼容旧版入口不增加此功能。

专注运行且此选项开启时，核心每250 ms枚举桌面顶层窗口；全屏按窗口可见边界与整屏边界匹配（2个物理像素容差），最大化按Windows窗口状态及所在显示器判断。检测所有窗口，而非仅检测前台窗口，因此通过快捷键移入窗口、鼠标拖入后最大化、切回主屏操作都能保持副屏亮度。最小化、隐藏、DWM隐藏的其他虚拟桌面窗口、系统桌面与任务栏、本核心的遮罩不算占用。检测与坐标比较沿用PerMonitorV2模式；没有窗口保持亮屏时，原有鼠标返回逻辑照常生效。

检测到占用后清除该副屏的离开计时，隐藏专注遮罩，并经现有串行设备通道恢复当前正常亮度；时间计划与手动亮度继续更新正常目标。最后一个符合条件的窗口还原、最小化、关闭或移走后，从检测到结束的时刻重新计算完整等待时间。等待时间为0时立即恢复自动调暗。此功能处理本应用的专注遮罩和亮度限制，不修改Windows整机睡眠或屏幕电源超时。

检测依据：[EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows)、[DWM窗口边界与隐藏状态](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。原生双屏窗口识别与假设备亮度恢复已验证，真实显示器的端到端恢复仍待体验验收。

## 每日计划长时间渐变

开发版保留「到达节点后开始渐变」语义，新增节点默认30分钟，每个节点可延长到下一个节点前，0分钟立即切换。亮度和色温使用 `t²(3−2t)` 缓入缓出；跨午夜、恢复运行直接按当前本地时间求值，不补播错过的步骤。原色参与渐变时以现有硬件近似模型的6500 K基线计算，返回原色的终点仍恢复原预设；实际预设切换与观感取决于显示器。计划色温保留整数K，手动色温仍按100 K步进；内屏不调色。

计划每秒计算一次，只读相邻节点、场景和当前进度，无展开的多日时间线、逐帧数组或每秒目标字典。硬件只写变化的整数亮度与RGB增益；沿用每屏串行通道和一个最新待处理目标，慢调用不会堆积请求。关闭面板后由核心继续运行。手动亮度、色温和点击场景立即响应，覆盖保持到下一节点。实时到达下一节点时，从当前正常目标开始渐变，仅保存一份逐屏起点；错过节点或显式恢复计划时仍按时钟直接求值，不重播。保存语言、当前专注和场景名称不会重新触发节点行为；实际计划定义改变时重算并应用。

自动检查覆盖6小时跨午夜渐变、原色双向过渡、0分钟、单节点、非法重叠、72小时逐秒模拟及10万次慢设备请求合并。模拟中计划计算新增分配0字节；该结果仅针对纯计算及合并路径，不代表真实进程已完成72小时资源验收。

## 登录自启

登录自启只有一条注册表条目：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `MonitorsFocus`，值为 `"<可执行文件>" --center --background`。旧托盘和历史版本写过的 `MonitorsFocus.ControlCenter` 由 `StartupManager` 一并清理，任务管理器“启动应用”里只显示一项，不会出现两个进程抢单实例。核心每次启动按配置校正该条目：安装位置改变或条目被改动后自动重写，已正确时不重复写当前条目，但仍检查并清理历史条目。

实际是否启动还取决于 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` 下的同名二进制值：首字节 `02` 为启用、`03` 为禁用。条目被禁用时 Run 值仍在，但登录不会执行，只改路径会继承禁用状态。`StartupManager` 在保存设置和核心启动时把该值校正为启用，关闭时一并删除，避免界面开关与实际启动不一致。

自启必须指向自包含包，不能用 `bin/Release` 下的框架依赖输出：登录会话没有 `DOTNET_ROOT`，若本机 .NET 10 位于 `D:\Apps\dotnet` 且未注册安装位置，启动会因找不到运行时静默失败。当前稳定位置为 `publish/app/core/MonitorsFocus.exe`，面板在同级 `publish/app/desktop/MonitorsFocus.WebHost.exe`；重新发布覆盖这两个目录即可保持自启有效。2026-11-01 已将包含全屏及最大化保持亮屏功能的新包原位替换，先正常退出旧核心并等待硬件恢复，再启动新版；已确认双屏检测正常、新选项开启、原配置文件未改动、自启仍指向上述稳定位置。

## 中英文与语言偏好

开发版「设置 → 通用 → 语言」提供简体中文、English、跟随系统。选择立即预览，不重建编辑器；切换设置页保留其他草稿，保存失败也保留。保存成功后持久化到 `control-center.json` 的 `Language`（`system` / `zh-CN` / `en`），托盘下次展开即使用新语言，无需重启。重新载入放弃草稿并恢复已保存语言；返回快捷面板沿用已有的设置草稿退出行为，同时恢复已保存语言。

已有控制中心配置缺少 `Language` 时默认跟随系统；首次从旧版迁移时继承其 English / Chinese / System 选择，不改写旧文件。系统界面语言为中文（含繁体系统）时使用简体中文，其他语言回退 English。核心返回系统语言，保证 WebView 的浏览器语言与 Windows 设置不同时，面板和托盘仍使用相同的系统语言。宿主在加载首屏前读取语言偏好，启动失败提示也跟随它；此读取失败不写配置。

应用文案统一维护在 `src/MonitorsFocus.Core/strings.json`，中文原文为键、英文为值，动态参数使用 `{0}`、`{1}`。Core 内嵌同一份资源，Web 导入并检查键类型；不要增加散落的翻译表。新面板覆盖五个页面、空态、图表、无障碍名称、桥接失败及核心的校验和硬件错误。兼容 WinForms 入口共用资源，补齐托盘、消息框、主屏标记和能力状态；切换语言保留未保存的调光模式与屏幕选择。系统/驱动返回的未知诊断与技术日志保留原文。

用户数据不作为翻译键。新建默认场景通过 `DefaultName` 标记显示日常 / Day、夜间 / Night、专注 / Focus；用户改名后清除标记。已有场景和用户自定义名称不推断、不重命名，时间计划来源也原样保留这些名称。语言切换不改变场景目标、绑定权重、计划或专注规则。

`LocalizationChecks` 检查资源参数一致性、系统回退、嵌套硬件错误、语言保存/旧版迁移、用户名称保留及旧编辑器未保存选择。隔离浏览器模拟桥已验证语言即时切换、跨页草稿、冲突失败后保留、放弃改动、保存后重新打开和英文快捷面板宽度；没有调用真实硬件。本轮集成已生成独立自包含包，未替换本机 `publish/app`。

## 硬件实测记录

本机双屏为 AOC U27G4（2560×1440，DisplayPort）与笔记本内屏 BOE。2026-10-31 用 dxva2 直读 VCP 复核，结论用于解释面板能力显示：

| 项目 | AOC U27G4 | 内屏 BOE |
| --- | --- | --- |
| DDC 亮度（0x10） | 可读写，0–100 | 不可用，走 WMI |
| 对比度（0x12） | 可读写 | 不可用 |
| RGB 增益（0x16/0x18/0x1A） | 可读写 | 不可用 |
| 直接色温（0x0E） | 不支持 | 不支持 |
| 色温步进（0x0C） | 可读 | 不可用 |
| `GetMonitorCapabilities` | 始终失败 | 始终失败 |

调色前若无法读取当前颜色预设，会报告失败并停止本次增益写入，避免未切换到用户模式却显示成功。

两个与实现直接相关的特性：新句柄的第一次 VCP 事务常被 NAK，所以 `DdcBrightnessDevice.Open` 在拿到句柄后先做一次丢弃读并等 150 ms；写 0x14 的「用户」值 0x0B 后读回为 0x01，恢复预设必须写回实际读到的值，不能用常量判断。

色温能力因此不作为一次性判定：首次读增益失败时 `ControlledDisplay` 会在后台按 2 s、6 s 间隔继续探测，探测走同一串行 worker，不与亮度命令并发。连续 8 次冷启动探测成功 7 次，失败均发生在句柄刚建立时，这是加预热的直接依据。
