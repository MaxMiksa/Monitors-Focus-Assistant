# A方案还原核对

参考：[A 随手调节](../candidates/controls-first.png)。采用左上快捷面板和右上时间计划结构；示例数字与曲线不作为设备能力或运行结果。当前前端为React/WebView2。

| 编号与区域 | 目标要求 | 核对方式 | 结果与差异说明 |
| --- | --- | --- | --- |
| 01 快捷面板 | 名称、滑条、百分比横向对齐，双屏首屏可见 | 桌面实拍 | 符合；修复DPI导致窗口偏小，实际双屏21%/50%读取可见 |
| 02 比例绑定 | 独立一行，开关与标签居中 | 桌面实拍 | 布局符合；真实比例写入仍待硬件验收 |
| 03 色温 | 左标签、中渐变滑条、右数值，分隔线分区 | 桌面/浏览器截图 | 符合；当前硬件探测不可用时禁用，显示原色，不伪造可用状态 |
| 04 场景与底部 | 场景和来源并排，底部暂停与设置 | 桌面实拍 | 符合；增加恢复原色；来源区宽度可继续微调 |
| 05 设置 | 左侧导航，主内容图表和编辑行 | 桌面实拍、独立审查 | 符合基本结构；独立审查要求增强选中项，已补蓝色文字、浅蓝底和左标记 |
| 06 字体 | 无衬线且只用14/16/24 | 浏览器计算样式与源码 | 实测只有14px、16px、24px；系统标题栏由Windows绘制 |
| 07 连续曲面 | 统一超椭圆角 | CSS与浏览器能力检测 | 已统一按钮/输入/表面；当前浏览器支持superellipse(2)，WebView2跨版本仍需验收 |
| 08 错误与编辑 | 失败不假装成功、保留草稿 | 模拟桥失败与页面切换 | 键盘滑条41%请求被拒后回到40%；设置页切换保留18:00草稿；配置Revision防止旧草稿覆盖 |
| 09 界面关闭 | 关闭释放WebView2，核心继续 | 本机进程观察 | 已验证宿主和本应用6个WebView2进程退出，核心继续运行 |

截图：[快捷面板实拍](../acceptance/react-controls-desktop.png)、[时间计划实拍](../acceptance/react-schedule-desktop.png)、[有明确标识的浏览器预览](../acceptance/react-controls-preview.png)。早期WinUI截图为历史过程，不作为当前验收证据。

合理差异：已移除全部应用快捷键及旧版热键设置，专注页提示通过面板或托盘暂停、恢复；场景快捷键取消需求。内屏不调色；色温仅硬件、数值为近似值。计划在节点后按 smoothstep 缓入缓出，新增节点默认30分钟，可设数小时且须在下一节点前完成；图表使用相同规则，原色按6500 K基线参与预览。没有计划显示空态。曲线预览当前编辑草稿，不会自动保存或写入设备。亮度数值为正常亮度目标，硬件写入完成/读回状态尚需进一步细分，不能据此宣称全部硬件行为已验收。

本轮检查：Web类型检查和生产构建、Oxlint、解决方案Release构建（0警告0错误）、7项假设备检查通过；生产npm依赖审计未报告漏洞。原npm镜像不支持审计，已改用官方registry完成本次审计，未更改用户全局配置。

资源观察为一次瞬时样本：关闭前宿主工作集约83MiB，6个本应用WebView2进程工作集各约18–142MiB；关闭后它们均退出，核心工作集约64MiB。各进程工作集有共享页，不能直接相加当物理占用，也不代表长时间低占用验收。

待用户体验与后续验收：真实双屏手动写入、比例绑定、外屏色温能力稳定性和恢复、计划长时间运行、休眠/热插拔、混合DPI。v2.0.0 已发布，上述项仍未验收。
